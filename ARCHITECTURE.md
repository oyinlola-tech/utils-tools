# Architecture

## Overview

Utils-tool is a **local-first, serverless-ready** FastAPI application with a
vanilla-JavaScript frontend. The same codebase runs in two environments:

| | Local | Vercel |
|---|---|---|
| Storage | `./storage/` filesystem | Vercel Blob (`STORAGE_DRIVER=vercel`) |
| Ghostscript tools (PDF compress, PDF→image) | available | **disabled** (no `gs` binary) |
| Everything else | available | available |

Environment-specific behavior is driven by the **capability registry**, never
by frontend feature detection.

## Layered architecture

Every tool module follows the same five layers:

```
route → controller → service → repository
                       │            └─ infrastructure adapter → bytes
                       └─ shared/file_inspection (validation)
```

1. **Route** (`*_route.py`) — FastAPI `APIRouter`, declares the HTTP surface
   (`/api/v1/tools/{group}/{action}`), upload limits, and response models.
2. **Controller** (`*_controller.py`) — request validation (all
   `ValidationError`s), calls the service, maps errors to unified HTTP
   responses.
3. **Service** (`*_service.py`) — pure business logic: parameters, defaults,
   output naming. Never touches HTTP or storage directly.
4. **Repository** (`*_repository.py`) — byte I/O through the storage
   abstraction; returns output bytes + metadata.
5. **Infrastructure adapters** (`app/infrastructure/`) — thin wrappers around
   third-party libraries:

| Adapter | Library | Used by |
|---|---|---|
| `compression/pillow_adapter.py` | Pillow | image convert/resize/metadata/watermark, background replace, social presets |
| `compression/ghostscript_adapter.py` | Ghostscript | PDF compression, PDF→image |
| `compression/pdf_adapter.py` | pikepdf | PDF merge/split/rotate/extract/from-images |
| `archive/zip_adapter.py` | stdlib zipfile | ZIP creation, page archives |
| `image/background_remover_adapter.py` | rembg + onnxruntime | background remover |
| `storage/` | local fs or Vercel Blob SDK | all repositories |
| devtools service | qrcode, python-barcode | QR/barcode/favicon |

## Module map

| Module | Routes (prefix) | Tools |
|---|---|---|
| `background` | `/api/v1/background` | remove, replace |
| `compression` | `/api/v1/compression` | image/pdf compressor + batch |
| `compression` | `/api/v1/images` | image compressor (quality-slider API) |
| `image` | `/api/v1/tools/image` | converter, resizer, metadata remover, watermark, social presets |
| `pdf` | `/api/v1/tools/pdf` | merger, splitter, rotator, extractor, PDF↔image, page count |
| `file_tools` | `/api/v1/tools/file` | analyzer, ZIP creator, duplicate finder |
| `devtools` | `/api/v1/tools/dev` | favicon, SVG optimizer, QR, barcode |
| `jobs` | `/api/v1/jobs` | batch job lifecycle (create/status/cancel/cleanup) |
| `capabilities` | `/api/v1/capabilities` | capability manifest |

Routes that produce files return a JSON result with a `download_url`
(`/api/v1/tools/{group}/download/{filename}`) backed by a short-lived
storage-generated URL; the frontend calls it via `apiDownload`.

## Unified API contract

- Base path: `/api/v1`
- Success: `{"success": true, "result": {...}, "details": {...}, "download_url": ...}`
- Error: `{"error": {"code", "message", "request_id", "status"}}`
  - `code` is a machine-readable string (`VALIDATION_ERROR`, `UNSUPPORTED_FORMAT`,
    `INVALID_REQUEST`, `NOT_FOUND`, `INTERNAL_ERROR`, …)
  - `request_id` is generated by middleware and echoed in the
    `X-Request-ID` header
- Every response includes `X-Request-ID` for traceability.

## Capability registry

`app/core/capabilities.py` declares all 28 tools with:

- `id`, `name`, `description`, `icon`
- `status` — `available` (or `unavailable` with a reason)
- `environments` — `("local", "vercel")` or `("local",)` when a system binary
  is required
- `requires_binary` — e.g. `gs` for Ghostscript tools
- `limits` — e.g. batch size, image size caps
- `notes` — human-readable caveats

`GET /api/v1/capabilities` returns the effective manifest for the current
environment. The frontend landing page renders only available tools; tool
pages consult it before enabling the run button. Unavailable tools render a
"not available in this environment" state instead of broken forms.

## Frontend

- `frontend/index.html` — capability-driven tool grid.
- `frontend/pages/{tool_id}.html` + `frontend/assets/js/pages/{tool_id}.js` —
  one page per tool. Pages are served by FastAPI at `/tools/{tool_id}`.
- `frontend/assets/js/pages/tool-kit.js` — shared bootstrap
  (`initToolPage`, `setupUpload`, `renderImageResult`, `renderFileResult`,
  `triggerDownload`) so page scripts stay thin.
- `frontend/assets/js/api.js` — `apiGet` / `apiUpload` / `apiDownload`.
- Client-side-only tools (cropper, editor, base64 pair, beautifier) perform
  all work in the browser with zero uploads.
- `frontend/assets/js/local/` — server tools that the browser does itself
  when it can. `apiUpload` offers every request to `local/index.js` first;
  a tool there answers in the shape of the API response it replaces, with
  download links that point at data held in the page, or declines with
  `null` and the request goes to the server unchanged.

| Request | In the browser | Left to the server |
|---|---|---|
| `/tools/file/zip` | always, where `CompressionStream` exists | — |
| `/tools/file/duplicates` | always | — |
| `/tools/file/analyze` | everything else | batches with a PDF, TIFF or AVIF |
| `/images/convert`, `/images/resize`, `/tools/image/resize`, `/tools/image/remove-metadata` | JPEG, PNG and WebP up to 16.7 megapixels, written as JPEG, PNG or WebP | AVIF, lossless WebP, animations, keeping metadata, larger images, invalid options |
| `/tools/image/palette-extractor`, `/tools/dev/favicon` | the image is reduced before it is uploaded | the tool itself |

The server remains the reference: the browser tests in `tests/browser`
run each local tool beside its endpoint on the same files and compare
the answers.

PNGs are written by `local/png.js` rather than `canvas.toBlob()`, whose
output is two to four times the size.

## Lifecycle & storage

- Batch jobs persist `metadata.json` inside a job folder; cleanup deletes
  expired jobs (`JOB_TTL_MINUTES`, default 30).
- The storage abstraction hides local disk vs Vercel Blob; both expose
  `save`, `load`, `delete`, `exists`, and `generate_download_url`.
- Upload validation (`app/shared/file_inspection/`) runs magic-byte
  detection, Pillow `verify()`, and `Image.MAX_IMAGE_PIXELS` protection.
